# 在聊天中比较重复笔记

聊天输入区点击“检查重复”，无需加载生成模型或配置云端密钥。已加载本地 GGUF 时，也可以问“这些笔记有没有重复的？”。两条入口执行相同的只读 `duplicates` 查询；模型只负责规划，不判断删除哪份。

默认检查当前知识库全部活动文档，引用资料时仅检查引用集合。“筛选与统计 → 对比重复笔记”可进一步限定标签、日期或相对路径。图片、音视频与联合素材的整理继续使用多模态工作台。

## 如何判断

1. 元数据执行器得到全部符合条件的文档 ID，空集合不扩大为全库。比较范围不受结果分页、语义 top-k 或工作台 200 份限制影响。
2. 读取已保存的各文档片段向量并计算归一化平均表示，无需重新嵌入。全文内容指纹识别内容一致的资料；去除开头 YAML 后的全文指纹识别正文一致但元数据不同的笔记。
3. 其余候选必须同时满足向量相似度阈值（默认 0.9）和正文字符特征重合阈值（0.6）。字符特征采用稀疏哈希 3–5 字符片段，降低共同日期、标签和模板带来的误报。

相似度不是重复概率。字符哈希有碰撞，平均向量可能忽略局部变化，阈值仍是启发式；候选需要阅读核对。“内容一致”依据保存的文本与原件指纹，“正文一致”仅忽略前置 YAML 和 CRLF 换行差异，不承诺原件字节完全相同。

## 展示与保存

聊天直接并排展示文件名、相对路径和两侧原文片段，窄窗口纵向排列；无须再打开来源弹窗。每侧展示最多 2400 字，比较使用完整保存的文本，原资料不截断或改写。结果、路径、判断依据及历史回答随会话与备份保存。

摘要显示实际检查数量、全部候选对数量及涉及文档数量；默认展示前 20 对，计划支持 `limit`（1–50）和 `offset`（最多 10000）。优先显示内容/正文一致，再按向量相似度排序。没有自动删除、修改原件或扩大文件权限。

```json
{"version":1,"operation":"duplicates","where":{"field":"tags","op":"eq","value":"工作"},"threshold":0.9,"limit":20,"offset":0}
```

## 资源与验收

基础设施按 128 行分块比较，只保留有界结果页，不存储完整平方矩阵或全部候选列表；仍需读取全部选定文本与文档向量，计算成本随资料数量平方增长。没有宣称无限规模，大库延迟与内存需要真实语料评测。

自动测试覆盖 205 份文档的完整范围、分页、跨库拒绝、空范围、共同 YAML 误报、正文一致、会话/备份往返以及 Markdown 安全展示。真实 MiniCPM 与 EmbeddingGemma 的隔离样例识别出部署笔记副本，没有调用云端或生成器。报告见 [真实模型验收](local-model-acceptance.json)，界面见 `previews/chat-duplicate-comparison.png`。
