# EmbeddingGemma 2 多模态能力攻略

本项目使用完整 EmbeddingGemma 2 的文本、视觉和音频编码器。提供图片查相似图片、文本与多图联合编码、音视频分段检索、分类、聚类、语义查重及共享 8192-token 预算管理。模型输出是向量；转录、看图生成和聊天由其他适配器承担。

## 在应用中使用

打开侧栏「多模态工作台」。所有操作作用于当前知识库，原有文档与图片也能参与。

| 功能                   | 操作                                           | 实际结果                                                              |
| ---------------------- | ---------------------------------------------- | --------------------------------------------------------------------- |
| 图片查相似图片         | 找相似图片 → 拖入图片或从库中选图 → 查找图片   | 查询图片生成视觉向量，与库内图片比较；同一图片的视觉/OCR 命中合并展示 |
| 图文混合查询           | 组合查找 → 输入描述并添加图片                  | 文字和图片进入同一次模型前向计算，得到联合向量                        |
| 多张图片联合编码       | 组合查找 → 添加多张图片，可附文字              | 每张图片独立出现在模型输入中，共同生成一个联合向量；不是各图向量平均  |
| 联合素材入库           | 收集一组素材 → 名称、说明与文件 → 保存到知识库 | 保存联合素材、检索向量与原件，可供后续检索和整理                      |
| 音频/视频检索          | 找音视频片段 → 描述内容或添加一段参考媒体      | 返回相关片段的起止秒数，可打开本地播放器并定位到片段开始              |
| 视频画面与声音联合编码 | 导入带声音的视频，也可附文字和多张图片         | 同段视频帧、单声道音轨与附加素材联合编码；纯视频也可处理              |
| 自动分类               | 整理已有资料 → 建议分类 → 添加类别             | 按标签原型相似度分配类别，低于阈值为未分类；结果可导出                |
| 语义聚类               | 整理已有资料 → 按内容分组 → 期望分组数         | 按语义分组；完全重合的资料可能少于期望组数，不生成虚构组名            |
| 去重                   | 整理已有资料 → 找重复资料 → 比较候选           | 区分索引内容相同和语义相似，可选择暂存其中一份；原件与索引快照可恢复  |
| 预算管理               | 查询或收集时自动检查；高级选项可手动预检       | 展示单段预算与分段数，超限明确标红；推理前还会核对最终处理器输入长度  |

默认入口按实际任务组织。文件可拖入；图片可从知识库按名称查找和分页选择。分类类别支持逐个添加与移除；去重候选并排展示并可移入回收站。超过 200 份的整理需要先选择范围，单次最多 200 份。

高级选项保留检索精度（768/512/256/128）、检索任务、结果数量、分类与去重阈值、容量明细和预检；默认不要求理解这些参数。支持按资料名称筛选范围与导出 JSON 结果。文本任务支持通用检索、代码检索、问题检索和事实证据检索；后两者负责查找候选证据，本身不会生成答案或判定事实真伪。

## 输入与时间定位

- 文档：TXT、Markdown、PDF 文字层、DOCX；图片：PNG、JPEG、WebP。
- 音频：WAV、MP3、M4A、AAC、FLAC、OGG；视频：MP4、MOV、MKV、WebM。容器内必须有对应且可解码的轨道。
- 文档和图片每份最多 20 MB，音视频最多 200 MB、60 分钟；联合素材最多 12 份、合计 240 MB。一次联合输入最多包含一个音视频，其他可为文字或图片。多个媒体可分别导入，再在统一空间检索。
- 音视频按 24 秒窗口处理。音轨解码为 16 kHz 单声道 float32 PCM；视频每秒采样一帧，单段最多 24 帧，并保留视频声音。视觉帧保持比例放入统一尺寸画布。
- 分段保留 `start`/`end`。媒体结果的文字仅来自用户实际附加文字，文件名和时间标签不冒充转录。
- 长纯文本按实际 tokenizer 预算无损分段；长查询取各段向量归一化均值。图文/多图组合超限时拒绝，不静默删图、截断或假称联合编码。
- 浏览器通过认证接口取本地原件，再创建临时对象 URL 播放；令牌不放入资源 URL。浏览器无法解码的容器会提示播放错误，可导出素材供本地播放器使用。图片保存的是去除元数据后的规范化 PNG，音视频保存原始字节。

## 8192-token 预算

预算由真实 tokenizer 计数的文字/任务前缀、媒体预算与 64-token 格式预留组成。默认图片约 280 tokens、视频帧约 140 tokens、音频约 25 tokens/秒；实现另外计入媒体分隔预留。预检展示估算，模型前向前检查处理器实际 `attention_mask` 长度。超过 8192 返回 `context_budget_exceeded`，不会写入索引。

长媒体分段避免突破单次上限，不代表把整段一小时媒体装进一个 8K 输入。分类、聚类和查重对长资料使用分段向量的归一化均值，不丢弃尾部片段。

## 向量维度与整理算法

文字搜图默认智能筛选：明确的标题/文字优先按本地 OCR 匹配；画面描述、参考图与混合输入使用语义筛选。结果不凑满，向量分数不是命中概率。高级选项可选「图片内文字」（没有文字命中就返回空）或「扩大搜索」，并调整视觉与语义门槛，最多显示只是数量上限。默认门槛 0.55、智能语义候选与首条最大分差 0.08 属于启发式；不同语料、模态或降维后的质量需另行评估，不宣称通用最优阈值。明确 OCR 匹配不受向量门槛影响。

768 维完整向量持久化到 Chroma，维持原有索引兼容。工作台可用 768、512、256、128 维：双方取相同维度的前缀，再进行 L2 归一化和余弦比较。该选择改变当前搜索/分析维度，不会把已存索引物理压缩；128 维的多模态质量应另外评估。

分类以 `Classification` 文本任务前缀编码标签和文本资料，媒体保留原生表示；分数为相似度，不是概率。聚类使用 `Clustering` 表示和确定性最远点初始化的球面 k-means；最多迭代 40 次，输出非空分组。语义查重使用 `SentenceSimilarity` 表示，两两计算候选；索引内容指纹相同可直接判定内容相同，仍由用户选择暂存。

一次整理最多 200 份资料，精确多模态检索最多 10000 个片段。大于该规模应拆分知识库或增加分页/专用索引适配器。这里的边界是资源限制，接口会明确报错。

## 架构位置

| 层       | 文件                                                       | 职责                                              |
| -------- | ---------------------------------------------------------- | ------------------------------------------------- |
| 领域     | `domain/multimodal.py`                                     | 纯数据输入、预算、向量归一化、余弦、暂存记录      |
| 应用     | `application/semantic.py`                                  | 联合索引、检索、任务整理、暂存与恢复              |
| 端口     | `application/ports.py`                                     | 编码器、解码器、原件与暂存存储协议                |
| 基础设施 | `infrastructure/embedding.py`                              | 完整本地模型、任务前缀、实际长度校验与推理        |
| 基础设施 | `infrastructure/media.py`                                  | PyAV 本地字节解码、采样、分段；媒体解码不访问网络 |
| 基础设施 | `infrastructure/payloads.py` / `archive.py`                | 原件与索引快照私有存储、原子写入                  |
| API      | `api/app.py` / `schemas.py`                                | 认证、上传与参数限制、资源和任务接口              |
| 展示     | `features/semantic` / `shared/components/MediaPreview.vue` | 输入、预算、结果、播放器与整理流程                |
| 组装     | `bootstrap.py`                                             | 唯一具体依赖组装入口                              |

原件、快照和 Chroma 都按模型与知识库隔离。引用和素材访问先检查库内成员；暂存后不参与检索且资源接口拒绝访问。恢复后重新写回同维度快照。入库失败清理本次原件，不留下半份素材。云端图片授权规则保持逐次独立，多模态工作台不调用 DeepSeek。

## 本地验收

安装完整依赖并准备权重后执行：

```bash
uv sync --project backend --extra embedding --extra ocr --group dev
uv run --project backend --no-sync python scripts/check_multimodal.py
npm run check
npm run build
```

真实模型验收包含音频/视频入库与同媒体检索、文本查音频、图片查询、各维度归一化检索、文字与双图联合编码、文字/图片/视频/声音联合输入、三个整理任务、超限拒绝及长文本无损分段。结果写入 `docs/multimodal-acceptance.json`。样例是自制图片、系统语音合成录音及自制视频；测试不能替代真实用户语料的质量评估。

自动测试另外覆盖实际 PyAV 分段、音轨尾部完整性、Chroma 持久化、跨库拒绝、认证、素材删除清理、入库回滚和可恢复暂存。若要在浏览器体验演示，可先启动本地服务，再运行 `scripts/seed_multimodal_demo.py`；它使用单独的「多模态验收资料」库。

## 官方依据

- [Google 模型说明](https://ai.google.dev/gemma/docs/embeddinggemma/model_card_2?hl=en)：四模态、共享上下文、任务前缀、维度、采样和数值精度。
- [Transformers EmbeddingGemma 2 文档](https://huggingface.co/docs/transformers/en/model_doc/embedding_gemma2)：联合输入、模态顺序、处理器和归一化方式。

本实现使用 float32，没有替换成伪造向量。音视频检索已经接入，音视频自动转录、音视频生成式总结和本地通用视觉描述仍属于独立生成能力，不在本攻略中冒称由嵌入模型完成。

## 工作台交互参考

参考 [Eagle 官方功能介绍](https://www.eagle.cool/blog/post/eagle4) 的素材预览与相似/重复任务分离、[Apple 照片搜索](https://support.apple.com/en-ie/guide/photos/pht64de33e5a/12.0/mac/27) 的搜索与筛选入口，采用任务入口→添加参考/说明→直接操作→预览结果的路径。仅借鉴交互，本项目仍使用本地 EmbeddingGemma 2 的语义比较，并不声称采用 Eagle 的视觉指纹算法或苹果的人脸/物体分类能力。

搜索/收集前自动容量预检，随后服务仍执行实际预算检查；结果摘要缺少 fits 字段时保留预检状态，避免成功结果显示“需要缩减”。结果完成后滚动至结果区域。没有自动永久删除、生成式媒体总结或写入分类标签。

查重默认使用 0.92 门槛，并只展示同类型的语义相似候选与索引内容相同条目，避免相关的录音/图片/视频混为重复项。可在界面解除类型限制，或在高级选项调整门槛。结果仍需人工核对；“索引内容相同”不等于原文件字节相同。导出结果与当前候选过滤一致。
