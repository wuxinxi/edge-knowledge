# 通用查询计划与本地执行

本地助手采用「输入 → 查询计划 → 校验 → 执行 → 结果与依据」的流程。EmbeddingGemma 2 负责语义表示和检索；计数、求和、分组和排序由本地 SQLite 执行。生成模型不能把自己编写的数字当作统计结果，也不能把检索 top-k 数量当作全量文档数量。

## 分层与职责

| 层       | 模块                                                | 职责                                                         |
| -------- | --------------------------------------------------- | ------------------------------------------------------------ |
| 领域     | `domain/query.py`                                   | 版本化 QuerySpec、布尔筛选树、允许字段和操作、输入校验       |
| 领域     | `domain/query_parser.py`                            | 明确检索与简单日期操作的本地快速编译；不确定时澄清           |
| 领域     | `domain/metadata.py`                                | 日期与字段标准化，保留写作、发布、修改、导入和目录月份的区别 |
| 应用     | `application/query.py`                              | 规划、范围校验、工具选择、执行和结果呈现                     |
| 应用     | `application/catalog.py`                            | 元数据索引迁移、增量维护及所有资料写入的统一边界             |
| 端口     | `MetadataReader`、`DocumentCatalog`、`QueryPlanner` | 隔离 YAML、SQLite 和云端模型                                 |
| 基础设施 | `infrastructure/metadata.py`                        | 有界 SafeLoader，拒绝重复键、别名和显式标签；保留原文件      |
| 基础设施 | `infrastructure/catalog.py`                         | 参数化 SQL，仅执行受限查询代数                               |
| 基础设施 | `infrastructure/planner.py`                         | 明确授权的 AI 模式下，调用 DeepSeek 输出 JSON 计划           |
| 界面     | `features/chat/QueryBuilder.vue`                    | 本地筛选与统计，不需要 API Key；结果进入现有会话             |

具体实现仅在 bootstrap 装配。旧的专项 `NoteStatistics` 服务和问句统计分支已移除，所有统计共享 QuerySpec 和执行器。

## 本地与 AI 的边界

- 本地模式不会调用 DeepSeek。普通检索和明确的年月计数可快速编译；已配置 GGUF 时可由本地生成模型规划复杂条件，也可以使用“筛选与统计”。无法可靠理解的问法会澄清，EmbeddingGemma 本身不承担语言规划。
- DeepSeek 规划需要设置明确选择云端提供方、客户端传入 `allow_planning: true`、存在资料与有效配置。纯本地请求只允许本地规划器；`/api/catalog/query` 直接执行显式条件，不调用任何规划器。
- 规划器只收到本次问题、允许操作、当前日期/时区、自定义字段名称和类型，不收到原文、文件名、字段值或字段覆盖数量。解读阶段按原有规则单独处理检索证据与图片授权。
- JSON 计划必须通过同一套校验，不能包含 SQL、库 ID、引用 ID、文件操作、工具名、结果或自编统计数字。无效输出和超时直接报错，不能降级成无关检索结果。
- “本机结果 · 本地模型规划”“本地模型回答”与“本机结果 · AI 规划”“DeepSeek 解读”区分规划/生成提供方和执行位置，标记随会话和历史回答保存。

本地快速编译只是成本优化。通用操作能力来自版本化计划和执行器；新增支持的字段或操作无需在聊天服务中增加特定问句分支。

## QuerySpec v1

支持 `list`、`aggregate`、`search`、`answer`、`clarify`、`duplicates`。布尔树使用 `all` / `any`，叶节点使用 `field`、`op` 和 `value`。操作包括等于、不等于、包含、任一值、大小比较、已标注和未标注。

`duplicates` 对完整筛选范围内的活动文档比较，`text_query` 必须为空，不能用语义 top-k 冒充全库检查。`threshold` 为 0–1 的有限数，默认 0.9；正文核验与内容指纹共同过滤候选。返回全量数量及有限候选页，两侧片段在聊天直接展示。执行与资源边界见 [重复笔记比较](chat-duplicates.md)。

字段覆盖标题、文件名、相对路径、类型、扩展名、标签、资料文字、大小、时长、片段数、标准日期，以及 `metadata.<字段名>` 的扁平自定义字段。自定义字段定义可从当前知识库的 schema 获取；不存在的字段会报错，不能产生假的零结果。

统计支持 COUNT / SUM / AVG / MIN / MAX。分组支持年、月、资料类型、扩展名、标签、文件夹及自定义字段；组数与完整统计独立于分页。数值缺失或不是数值时不会按零参与计算。标签是多值字段，一个文档在单个标签组内只计一次，不允许把各标签数量相加当成总文档数。

排序支持字段、方向；分组结果可按 key/value/count 排序。分页限制为每页 1–50 项，跳过最多 10000 项，统计总值始终覆盖完整匹配集合。

例如：按季度时间范围筛选有明确标签的文档，并按月计数：

```json
{
  "version": 1,
  "operation": "aggregate",
  "metric": "count",
  "where": {
    "all": [
      { "field": "kind", "op": "eq", "value": "document" },
      { "field": "tags", "op": "eq", "value": "work" },
      { "field": "authored_date", "op": "gte", "value": "2026-07-01" },
      { "field": "authored_date", "op": "lt", "value": "2026-10-01" }
    ]
  },
  "group_by": "month",
  "group_date": "authored_date",
  "limit": 20
}
```

将 `metric` 改为 `sum`、`metric_field` 设为 `metadata.hours`，即可汇总笔记头部的真实工时字段。界面中输入真实字段名称即可，内部命名由客户端转换。

语义搜索可以与元数据条件共同使用：先得到全部符合条件的文档 ID，再对该集合检索。没有候选资料时直接返回空结果，不能把空 ID 集合解释成全库检索。媒体检索根据计划执行后的实际资料类型选择原有多模态检索器，不重新靠问句判断类型。

`aggregate` 的 `text_query` 必须为空。“与某主题语义相关的总共有多少份”需要定义分类标准或提供已经确认的标签，不能用相似度返回的前几条伪装成精确统计。明确的文字条件可使用 `text contains`。

## 索引与兼容性

元数据 SQLite 文件位于 `data/catalog/<模型命名空间>.sqlite3`。文档 ID 是知识库内的主键；同名文件不会被错误合并。新导入、目录替换、单个/批量删除、归档、恢复、备份恢复均通过 `IndexedKnowledgeRepository` 更新该索引。

索引是原件和活动向量记录的派生数据，不能成为新的原文事实来源。首次访问旧知识库时自动补建，版本指纹变化时增量更新；索引缺少记录时可重新补建，不调用嵌入模型，也不重新扫描目录或扩展文件权限。更新失败时不留下新的半成品文档；原件、向量、回收站和其他库仍受原有事务与范围保护。

原始文档通过 payload 文本端口读取；图片通过已保存的本地 OCR 文字读取，不载入原图字节，不推断图像内容。原始 YAML、正文、OCR 状态和原件仍完整保存。较旧且缺少完整 payload 的资料可提供元数据，但无法保证全文筛选；需要重新同步补齐后才能对其全文作精确筛选。

写作优先使用创建日期，再使用发布日期/date，不能用修改或导入时间填补。目录月份只提供单独标注的归档依据。导入时间保留完整时间戳，按请求的 IANA 时区转换后比较和分组，避免 UTC 月末与本地月份不同。Markdown 中声明的日期按该记录的日历日期读取。

查询只覆盖当前知识库的活动资料，或用户提供的引用集合。原始授权目录边界、图片上传授权、模型命名空间隔离及密钥处理保持原有规则。

## 验证

回归覆盖布尔组合、日期范围、数值聚合与缺失值、分组、多标签、分页、SQL 参数绑定、拒绝越权计划、拒绝语义 top-k 计数、索引重建、归档/恢复、备份恢复、月末时区、原图片检索路径、AI 模式门控，以及查询条件的会话保存和重试。

DeepSeek 适配器按 [官方 JSON Output 约定](https://api-docs.deepseek.com/guides/json_mode/)使用 JSON 模式，再由领域校验器验证实际内容。自动化验证使用隔离的模型响应，未向真实 DeepSeek 账户发送测试资料。复杂自然语言的规划质量仍依赖所选生成模型；执行范围和计算正确性不依赖模型提供的答案。

## 本地规划更新

默认提供方现为本地 GGUF。纯本地查询也可以使用 LocalQueryPlanner，DeepSeek 仍仅在明确选择云端助手时允许调用。本地快速编译与本地规划都不发送资料。年月统计采用共享日历约束，模型遗漏的明确日期由确定性编译器保留，改变条件则拒绝；其他复杂条件仍由模型输出并经过 QuerySpec 校验。见 [本地模型](local-model.md)。

## 查询面板的使用

“资料工具 → 筛选与统计”按用途分为找资料、做统计和检查重复；常用入口提供按月份统计、按标签看数量与找未标日期的笔记。资料范围显示当前知识库或引用集合，条件按字段、匹配方式和值排列，日期比较采用早于/不早于等文案。数值汇总、自定义属性、分组、排序及分页保留在相应用途和更多选项中。

月份控件编译成起始日（含）和次月首日（不含）的独立约束，与其他筛选条件相交；把其他条件改为任一符合也不会把月份变成可选条件。跨年月份以日历字符串计算，不依赖 UTC 日期换算。预览、错误和执行按钮固定在底部；展示项数只影响预览。切换到查找或比较不会携带隐藏的统计字段；统计来源默认折叠，计算结果标为本地统计，原始依据与计划仍保存。
