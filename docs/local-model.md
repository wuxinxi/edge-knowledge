# 本地模型优先

本地助手默认使用 GGUF 文字生成模型。EmbeddingGemma 2 继续负责文档、图片和媒体的语义检索；MiniCPM 等生成模型负责查询规划与依据资料回答；全量筛选和统计由 SQLite 完成。它们是独立的角色，换生成模型无需重建已有向量库。

## 使用

本次开发环境已在忽略提交的 `.env` 中配置用户指定的 MiniCPM5-2B-Q4_K_M 文件和本机 llama-server。重启 `npm run dev` 后，进入“偏好设置 → 模型”，确认“本地模型 · 不上传资料”，点击“保存并加载模型”，或直接从聊天中的“本地助手”提问。

模型文件可以在设置中改为其他完整 GGUF 路径；运行程序留空时查找 PATH 中的 llama-server，桌面 PATH 不包含它时填写完整程序路径。默认本地上下文为 8192。设置会持久化；模型首次使用时加载，后续复用。切换模型文件或上下文后，下一次使用重新加载。不会复制、上传或自动下载权重。

“查找资料”直接展示检索证据，必要时允许本地模型规划，始终禁止调用云端。“本地助手”还可以依据检索文字生成回答。DeepSeek 需在模型设置明确选择云端提供方并配置密钥；只有云端助手请求允许 DeepSeek 规划和回答。本地模型不可用或规划无效时直接说明失败，不自动转向收费服务。

## 实现与边界

- `LocalModelRuntime` 是应用端口，bootstrap 注入 `LlamaRuntime`、`LocalQueryPlanner` 与 `LocalGenerator`。API 与应用层不导入推理基础设施。
- 推理运行于应用拥有的 llama-server 子进程，仅绑定 127.0.0.1，使用独立随机令牌与私有临时密钥文件，关闭日志并开启 offline。请求禁用环境代理与 HTTP 跳转；模型端点不允许任意外部地址。应用正常关闭会回收子进程和临时文件。
- 本地规划使用少量结构示例和 schema 约束，所有输出仍经 QuerySpec 校验。不允许模型提供 SQL、文件操作、库 ID 或统计答案。原文不进入规划阶段。
- 明确的年月统计条件由共享日历解析器计算并合入模型计划，遗漏的日期不能扩大统计范围；模型改变日期则拒绝执行。年份不明先澄清。日级范围、多日期与季度不由该快速解析器擅自推断为整月，复杂规划的正确性仍需结合模型与实际查询条件判断。
- 输出严格区分本地规划、本地生成、云端规划和云端生成；来源标签随会话、历史回答和备份保存。
- 通过运行程序的 apply-template 与 tokenize 检查实际本地模型上下文，并预留生成空间；超限报错，不截断原始会话或偷偷省略证据。达到生成长度上限会在回答中说明。
- 内容目标判断和最终回答使用模型模板支持的推理模式，运行器分开解析推理与最终正文，推理预算 256 tokens，仍计入各请求总输出上限。聊天只接收最终正文。推理结束但正文为空时，在同一模型和同一依据上关闭推理重试一次；再次为空明确失败，不自动转向云端。具体策略与质量检查见 [问答质量](answer-quality.md)。
- 当前 GGUF 适配器仅声明文字能力。图片查找由 EmbeddingGemma 与已保存 OCR 完成；图中文字可交给本地文字模型解读。没有接入视觉投影器，不能把它当作原生看图模型。音视频检索不等于转录与生成理解。
- 查询规划器只执行已有的只读查询操作。文档/笔记重复比较已接入聊天，分类、聚类和媒体整理仍由工作台提供；接入本地模型不能据此宣称所有自然语言任务完成。见 [聊天重复比较](chat-duplicates.md)。
- 打包发行还需提供对应平台的 llama-server 或明确安装要求；Windows/Linux、干净机器与正式安装包未做本轮实机验收。正常退出之外的强制杀进程/断电恢复属于既有发行与后台作业待办。

llama.cpp 的接口与 JSON schema 约束参考[官方 server 文档](https://github.com/ggml-org/llama.cpp/blob/master/tools/server/README.md)。模型运行方式参考 [MiniCPM5-2B-GGUF 模型卡](https://huggingface.co/openbmb/MiniCPM5-2B-GGUF)。

## 验收

`scripts/check_local_llm.py` 显式接受 GGUF 与嵌入模型路径，在临时目录建立演示库。实际运行真实 MiniCPM 与真实 EmbeddingGemma：月份创建统计、标签分组、缺少日期报告、年份澄清、部署步骤查找、本地带引用总结、目标图片检索、笔记副本比较通过；未配置云端密钥或调用云端。报告见 [local-model-acceptance.json](local-model-acceptance.json)。这些是隔离样例，不代表任意真实语料的质量保证。

## 2026-10-15 原生模板输出边界

真实本地重放发现部分回答的 `content` 含前置 `</think>`。适配器现在统一过滤开头的原生推理框架：识别跨片段拆分的开始/结束标记，丢弃前置推理块；块内只保留结束标记长度的尾部，不积累或发送推理全文。正常正文开始后不再扫描替换，正文里的代码示例保持原样，普通正文的前导空白保留。

只返回标记、只有推理或未闭合推理块都不算有效答案，继续使用原有同模型、同依据的一次空回答恢复，失败明确报错。流式和非流式使用相同边界处理，调用前的完整输入与 token 预算检查保留；这是传输边界修复，不承担事实正确性的验证。回归覆盖逐字符分片、孤立结束标记、完整及未闭合推理块、正常代码文字、空回答恢复与最终失败。
