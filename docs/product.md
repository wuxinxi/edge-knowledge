# 产品方向：电脑本地助手

## 定位

**Edge Assistant：帮你找到、理解和处理电脑里的资料。**

产品的入口是本地助手，知识库是第一项能力。用户提出的任务可以是“找出上周那张报销截图”“会议录音里什么时候讨论了交付日期”“根据项目文档整理下一步工作”。这比只提供上传 PDF 后问答更符合 EmbeddingGemma 2 的多模态检索方向。

目前已实现文本、图片、音频和视频检索，图文与多图联合编码、媒体时间定位、本地 OCR、带来源问答、分类、聚类、语义查重与可恢复暂存。完整模型能力说明见 [多模态攻略](multimodal-guide.md)。文件/目录只读授权、手动扫描预览、选择导入和撤销访问已实现。文件夹来源与每分钟增量同步已接入；系统文件操作、音视频自动转录与生成式总结尚未实现。

## 三项产品能力

| 能力     | 用户目的               | 当前能力                               | 后续方向                         |
| -------- | ---------------------- | -------------------------------------- | -------------------------------- |
| 找资料   | 用自然语言找到本机内容 | 导入文本/图片/音视频，跨模态检索与定位 | 大目录分页与规模验收             |
| 理解资料 | 总结、解释、比较、引用 | 本地图片识字、OCR 问答及授权云端看图   | 多模态证据与本地生成模型         |
| 处理资料 | 整理并产生可用结果     | 分类、聚类、查重、暂存恢复与结果导出   | 导出摘要、整理文件、受控执行任务 |

文本、图片、音视频与资料整理现已具备可用入口，目录来源支持增量同步与暂停，后续推进大目录分页、生成式媒体理解和受控文件任务。图片检索是参考文章中最值得优先验证的扩展场景；中文音频的实际效果需要单独评测。

## 架构如何支持这个定位

保持分层依赖方向，将能力扩展落到对应层：

1. **展示层**：助手入口、搜索结果、资料管理、任务反馈。组件不处理嵌入或执行文件操作。
2. **API 层**：每项能力有独立的输入校验与事件协议，不把 HTTP 参数贯穿整个业务层。
3. **应用层**：导入/索引、搜索、问答、文件任务分别是独立用例。当前 `knowledge.py` 和 `chat.py` 已分开。
4. **领域层**：当前文档与片段实体；加入媒体时引入资源类型和来源定位，图片、页码、时间戳均能指回证据。
5. **基础设施层**：文本/视觉/音频编码器、目录扫描、存储、DeepSeek、系统文件操作各自实现端口。当前开启完整文本、视觉和音频编码器，媒体采样与上下文预算由独立适配器及领域规则处理。
6. **宿主层**：Electron 管理授权目录与本地能力，未来文件操作只能通过有范围限制的端口执行。

嵌入模型负责相似度检索，不能单独完成文件操作或回答生成。未来多模态资源即使在统一向量空间里，也应保留独立的模态信息、来源、模型版本和索引状态。当前查询结果可呈现图片与 OCR 证据；DeepSeek 适配器按具体模型能力选择文字或图片内容块。音视频语义检索与片段播放已接入；自动转录和生成式理解需独立适配器。

## 本地与联网的产品表述

- 文档索引、嵌入、检索和存储在本机。
- 初次使用嵌入模型需要下载；离线运行要预先准备缓存。
- 生成阶段通过 DeepSeek API 联网发送问题与相关文字片段；云端看图另须逐次授权发送图片。独立图片识字与资料检索可离线运行。
- 未来增加本地生成适配器后，可提供独立的全离线模式。
- 目录自动索引只访问用户明确选择的位置，文件整理与执行任务另行定义预览、确认、日志与撤销能力。
