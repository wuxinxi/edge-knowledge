# 通用资料读取与连续查询

这是查询执行层的能力扩展，不是某个标题或“总结这篇文章”的问句补丁。

## 查询契约

`QuerySpec` 增加 `read` 操作及两个显式字段：

- `source_scope: excerpt | full_document`：回答依据检索片段还是完整保存的资料。完整范围不会受 top-k 或每片段 4000 字符截断影响。
- `use_context: boolean`：是否使用本轮传入的资料上下文。上下文只是一组合法资料身份，不会自动变成所有问题的强制过滤范围。

`read` 先使用现有目录索引和结构化条件解析资料身份，再调用统一的原文读取能力；自然语言规划器可以提供标题片段 `text_query`，或使用 `title` / `filename` / `path` 条件。身份不唯一时返回候选，请用户选定；不是把向量前几条拼接成全文。明确的阅读全文按钮直接提交 `read` 计划，不需要模型判断。

`answer` 可以声明 `full_document`，读取筛选范围内的完整保存文字。针对当前资料的计划设置 `use_context=true`，独立新主题则为 false。比较、翻译、清单整理或其他问答复用这同一条执行路径，不在执行层识别“总结”“SenseVoice”等特殊问句。统计和查重继续使用各自只读工具，不交给生成模型猜测。

## 分层与权限

领域层定义计划、证据范围和校验；应用层 `DocumentReading` 与 `KnowledgeService.read_document` 通过既有仓储、目录和原文存储端口读取资料。没有新增应用层文件系统访问，具体存储仍由 bootstrap 组装。

资料 ID 在读取目录或原文前校验当前知识库归属。显式引用是查询边界；模型使用的上下文必须与显式引用相交，不允许扩大访问范围。缺少保存原文时返回 `original_missing`，不拿重叠切片冒充全文。

自然语言规划只接收问题、只读契约、必要目录元数据和可用上下文，不接收文档正文。阅读全文只用原文存储，不进行向量推理。回答才把相应的完整资料交给明确选择的生成服务。

查找模式下，有可用上下文的后续请求经同一查询事件通道处理，允许本地规划器选择查找、阅读、统计或解读；执行策略 `local_generation_only` 强制本地生成。它是请求级策略，不更改用户的全局模型设置，也不会因本地失败自动调用 DeepSeek。

## 对话与呈现

打开一份完整资料后，将其建立为可见的当前资料引用，复用已有引用控件；用户可移除引用或打开另一份资料来切换工作对象。当前引用是明确的查询边界，模型不能仅凭判断“不相关”就越过范围。每轮还从最近一次成功的证据提取资料身份作为可选上下文，不扫描用户问句关键词。上下文与显式引用分别传递并随原始用户消息保存，重试使用原请求范围，刷新和备份后保留。新会话没有前一会话的上下文。超过上下文数量预算时不会偷偷取前十份当成全部资料。

结果用 `content_scope` 区分片段和完整文档。阅读卡片提供展开全文、复制全文和总结入口；普通检索提供阅读全文。全文仍可折叠以控制聊天长度，但正文实际保存完整，不是视觉展开后再展示另外一个 top-k 片段。

## 验证与边界

通用合同测试覆盖任意界面文案、不同标题和资料主题、全文与片段的区别、明确身份与多候选、上下文被计划采用/不采用、显式范围冲突、跨库和已删除资料、缺失原文、本地策略、保存恢复及无效计划拒绝。

用户的 SenseVoice 文章只作为一个真实验收样例：隔离副本读取并校验完整保存文字，再向本地生成模型提供完整资料。验收在临时知识库副本中进行，不写入生产知识库或会话，不复制云端密钥。

“完整资料”目前指已导入文档保存的完整解析文字；Markdown/TXT 保留文字，PDF/DOCX 是导入时解析的文字，不等同于原版排版。完整原文只在资料原件存在时可用，未实现的音视频转录不能冒充全文。一次完整回答上限为十份资料；本地模型继续核对真实 token 预算，超出 8K 上下文时明确拒绝，不静默截断或宣称完成了整篇总结。分段汇总、结构化引用核验和更大范围的对话规划质量仍需后续打磨。

最终检查通过 421 项测试（151 TypeScript、270 Python）。真实 SenseVoice 样例的读取文字 3663 字符与保存原文逐字一致；后续以当前资料引用执行回答，完整原文保留，来源范围未变化。一次隔离重放得到带 [1] 引用的本地回答；这个结果不等同于通用生成质量保证。浏览器演示使用单独的合成笔记，验证刷新后资料引用仍可见、全文确实可展开至末尾、后续请求带本地策略、没有页面错误；截图文件为 `previews/article-reading-flow.png`、`previews/article-summary-followup.png`。
